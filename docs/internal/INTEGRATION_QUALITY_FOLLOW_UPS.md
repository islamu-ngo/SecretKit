# Integration quality follow-ups

These gates do not defer the integration-quality offline implementation.
They preserve ownership of claims requiring different evidence or authority.
No entry grants remote execution or publication.

| Follow-up | Owner | Trigger | Required evidence |
| --- | --- | --- | --- |
| Provider-specific hosting package extraction | SDK maintainers | A second provider needs a real hosting contract | Two implemented contracts, package graph and migration proposal; not an empty abstraction |
| Trimming and Native AOT qualification | Runtime qualification maintainers | A supported consumer requires those deployment modes | Exact selected archives, runtime/platform, analyzer and installed execution results; ordinary JIT success is insufficient |
| Remote source debugging | Package maintainers | Commit-bound published source is authorized and available | Actual SourceLink URL resolution and matching document checksums for selected assemblies/PDBs |
| Native Infisical conformance | Provider engineering maintainers | Authorized deployment/version, identities and entitlement inputs exist | Existing full native cases and supplements, independent effects, policy and network evidence |
| Event-side adoption | Event maintainers | A separately authorized Event integration task | Event-owned requirements, selected SecretKit originals and application tests; no implementation copying |
| Public package release | Release maintainers | Explicit publisher authority and release approval | Existing seven-package public admission protocol, provenance and checks; local qualification is insufficient |

The [current preview](../public/current-preview.md) and
[provider support](../public/provider-support.md) own current support claims.
The [local readiness contract](INFISICAL_LOCAL_READINESS.md) owns local-profile
qualification. Keep blocked provider-engineering contracts and their original
denominators; do not translate absence of native authority into an offline pass.
